# 0.5.0 — plugin foundation (candidate)

## Implemented

- Trusted plugin composition, no approval or capability-authorization layer.
- Plain-JS runtime for exact-version services, dependency ordering, scoped cleanup and contribution registries.
- The built-in execution adapter uses the same runtime as installed web plugins.
- Native immutable package staging, integrity hashes, lazy dex loading, pinned calls, revision rollback and disable-all recovery from Android Settings.
- Agent `plugins` management tool; standalone Kotlin/D8 build script, authoring skill and counter example.

## Boundaries

This is milestone M1, not completion of the entire core-as-plugins migration. Chat, sessions, storage and credentials have not yet been extracted. Native replacement after a loading attempt requires a process restart. Web composition is page-scoped. No additional Android permissions or native plugin screen host were added.

## Verification

45 combined web/source-packaging/browser-entrypoint/handoff tests pass; all browser modules pass Node syntax checks. Kotlin production sources compile and Gradle assembleDebug succeeds. The candidate is signed and verified against the pinned app certificate by build-apk.sh.

All 15 native foundation checks pass in permission-aware JVM execution (nonzero UID/GID under PRoot), including traversal, immutable snapshots, recovery, pinned revisions and the web/native composition boundary. Build tooling compiled the example twice, verified deterministic dex and host/tool hash agreement, and verified failed builds preserve the previous output.

On-device WebView startup, native DexClassLoader calls and recovery after process death remain unverified until installation/testing. Do not equate static/JVM checks with those checks.
