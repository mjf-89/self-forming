# 0.6.3 — the remaining Kotlin halves move into their plugins; relay CSP for Tor/Tailscale (X3n, X4n, X5, N4; candidate)

## Native (Kotlin)
- core-storage (X3n): `SqliteStore`, `SqlScript` and the `sqlite.*` routes (`CoreStorageNative`, same single SQLite
  thread, same database files `noBackupFilesDir/databases/<name>.sqlite`).
- core-net-native (X4n): `NativeHttp`, `NativeHttpPolicy`, `HttpUpload`, `HttpAllowList`, the `http.*` and
  `http.allowList.get/set` routes and the `nativeFetch`/`httpAllowList` flags (`CoreNetNativeNative`).
- core-secrets (X5): `SecretStore`, `SecretBroker`, `SecretPrompt`, `SecretPrompter`, `Redaction`, the `secrets.*` routes,
  the `secrets`/`secretBroker` flags and the USE_BIOMETRIC permission (manifest fragment). Keystore keys, `secrets.json`,
  scopes (agent/terminal/servers), biometric rules and redaction unchanged. core-execution reaches them through the host
  interface `CommandSecrets`; MainActivity through `ActivityHooks`.
- Providers (X5): the host keeps the `auth.*` dispatcher (`NativeAuth`) and the shared credential store (`AuthStore`, also
  used by plugin credentials). core-providers-chatgpt declares the "chatgpt" provider and owns the loopback sign-in
  (`auth.listen/open/wait/cancel`, `AuthUrls`); the new `plugins/core-providers-claude/native` declares "claude", owns
  `auth.openExternal` (`ClaudeAuthUrls`) and the `claudeAuth` flag. Record paths and Keystore aliases unchanged: sign-ins survive.
- Same bridge method names, JSON shapes and `host.info` capability flags as 0.6.2. A build without any of these plugin
  folders still compiles; the missing routes answer METHOD_NOT_FOUND and their flags are absent.

## Page CSP (N4)
For the network route plugins over `libs/cors-rot` (Tor via Snowflake, Tailscale), `MainActivity` now allows:
- `connect-src` + `'self'` (tailscale-client.js fetches its own `tailscale.wasm`), `wss://snowflake.torproject.net`,
  `wss://*.snowflake.torproject.net`, `https://snowflake-broker.torproject.net` (+ `:8443`), `https://*.tailscale.com`,
  `wss://*.tailscale.com` (list and reasons: `BrowserConnections.RELAY_CONNECT_SRC`);
- `frame-src 'self'` and, for `…/snowflake-proxy.html` only, `frame-ancestors 'self'` (the hidden Snowflake proxy frame);
- the request filter lets the HTTPS relay requests (Snowflake broker, `*.tailscale.com`) through from the app origin;
- `.wasm` is served as `application/wasm`.
Not verified on a device: Tor/Tailscale through the WebView.
