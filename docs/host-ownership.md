# Host ownership list

Rule: a built-in plugin's implementation (web **and** Kotlin) lives in `plugins/<id>/`. The host folders keep only the
runtime, contracts and genuinely shared code. `tests/plugin-ownership.test.mjs` enforces this list: every checked host
file must be listed here, either as host code (with the reason) or as **pending** (with the step and target plugin).
Unlisted checked files and missing listed paths fail the test. Detecting implementation twins still requires review.

Host folders checked: `apps/common/*.js`, `apps/android/app/src/main/java/**.kt`; `native-host.js` imports are scanned
in those JavaScript files and `plugins/*/web/**/*.js` against "native-host.js importers"; and imports (static or `import()`) from
`apps/common` into `plugins/*/web` (served `./builtin/<id>/web/…`) except those listed under "bundled-fallback imports",
each with the service or contribution of the owning plugin it falls back for. The generated registry
`builtin-plugins.js` is exempt: it imports only the plugins' `web/index.js` entries.

## libs/cors-rot (pinned upstream copy)
`libs/cors-rot` is never edited by hand. It is a pinned copy of github.com/mjf-89/cors-rot; update it only with

## Browser installed-plugin lifecycle boundary

`core-plugin-management/web/browser-plugin-host.js` owns workspace validation, snapshot publication and page-pinned lifecycle; `browser-plugin-package.js` owns canonical paths/schema/digest; `browser-plugin-store.js` owns the separate IndexedDB code store; `browser-plugin-serving.js` owns fail-closed immutable response construction. Browser host only dispatches methods; browser-main supplies the shared VFS, deployed built-in inventory and controlling-worker readiness. SW routes the reserved namespace before editable app revisions or network fallback.

Only those four exact owner modules are fixed in the browser recovery bootstrap: corrupting installer, integrity, durable pointers or serving could otherwise make recovery management unavailable or override immutable code. Other core-plugin-management files (including Settings, provider UI and agent tool) remain editable. Existing mandatory browser/provider/execution fixed boundaries are unchanged. SW imports the serving module by its assembled `builtin/` path; build output lists every deployed built-in ID independently of editable registry code.
